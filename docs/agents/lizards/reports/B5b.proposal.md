# B5b proposal (step 1: analysis only; nothing implemented, no browser run)
**Pick: a per-instance attribute, not a flow texture.** `flow` = vec4 InstancedBufferAttribute on each plant geometry = (prevX, prevZ, nextX, nextZ) in cm/s, in the plant's local frame. A uniform `AIR.blend` (0..1 across the 0.4 s sample window) mixes prev to next in the shader; the only per-frame work is one uniform write next to the AIR.flow write (airflow.js:62-63).
**Why attribute:** (a) flow is read at the plants (cap 300 per species, plants.js:609), not at every hydro cell; (b) the filter jet and intake (`poolCurrent`, filterflow.js:86) are analytic and NOT in vx/vz (hydro.js:55-56, :628-635), so only a per-plant CPU sample can add them, a texture would have to rasterise them; (c) no new sampler in a vertex stage (Safari WebGPU already bit us in the Low substrate shader), just an attribute like `sway` (shaders.js:287) and instanceColor (plants.js:640); the scene pass is untouched, only the plant material's own graph changes, and only when built with an opt-in `flowBend: true`.
**Plumbing:** sim/plants.js addMesh :633-642 creates the attribute; writeInstance :748-790 and remove :752 write/zero it for the moved instance. airflow.js gains `plantFlow(world)` inside the existing 0.4 s sample (:60-61): per plant `hydro.vx/vz[cellOf(x,z)]` (hydro.js:101) + `poolCurrent(H,x,y,z)`, rotated into local by q^-1 (p._q, plants.js:777), a quarter of the plants per frame, `needsUpdate` only if some |delta| > 0.3 cm/s; a plant in a dry cell reads 0.
**Pure function** (src/util/plantbend.js): `plantBend(flowX, flowZ, speed, height01, stiffness)` -> {x, z, sag}: dir = flow/|flow| (0 if no flow); lean = BEND_MAX * tanh(speed / (V50 * stiffness)) * height01^2 (tip > base, monotone, capped); sag = lean^2/2 so a blade does not stretch. BEND_MAX, V50 are exported and imported by the shader, so JS and TSL share the numbers. Species get `material.stiffness` (vallisneria low, sword high, default 1) in plants.js:333-509.
**Shader** (shaders.js:285-299 only): steady lean (weighted by the existing per-vertex `underw`) plus the old sin/cos wobble scaled by speed, so a plant leans with the water and flutters on top.
**Aquatic = who bends:** habitat 'aquatic' (Vallisneria :302, Amazon sword :336, Java fern :365, Fissidens :465, Rotala :489) fully; 'emergent' with an underwater material (Anubias :390, Java moss :411, cattail, sedge, creeping jenny, grass tuft) bend only where a vertex is under water (`underw`, :278); 'floating' (frogbit :512, water lily :530), land and wall: none (they keep the AIR.air path). decor tufts (decor.js:540) and litter (litter.js:47) stay on the scalar (not my files; the flag is opt-in).
**Test** (tests/plantbend.test.mjs, written failing first): lean within 10 deg of flow for 8 directions; monotone in speed; zero at zero flow; tip (h=1) > base (h=0.3); speed 1e6 gives <= BEND_MAX; stiffer leans less. **Page number:** `window.__AIR.probe()` -> {errDeg, speed, version}: a Vallisneria 5 cm downstream of the return (hydro.ports.ret dx,dz) has its `flow` next-vector within 10 deg of (dx,dz) in world frame, speed > 0, attribute.version rose; all zero with the pump off.
**The unit test cannot cover:** the TSL port (the shader repeats the formula; node cannot run it), the q^-1 local-frame rotation and the prev/next blend, hydro really pointing along the jet, how it looks (stretch, popping at the 0.4 s step), WebGPU/Safari compile of the changed plant material, frame cost: those need a browser step (screenshot + CPU ms).
**Noticed, not touched:** `underw` (shaders.js:278) compares the plant's LOCAL y with the world water level, so a short plant on a high ridge counts as submerged; my dry-cell gate covers the new term only.
